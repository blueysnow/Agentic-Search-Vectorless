Purpose: Phase 2 ingestion pipeline design cannot be finalized until we have empirical data on PDF math extraction quality. This script produces that data.

<task type="auto">
  <name>Task 1: Add pymupdf4llm dependency and create validation script</name>
  <files>pyproject.toml, scripts/validate_pdf_math.py</files>
  <action>
1. Add `pymupdf4llm>=0.0.17` to the `dependencies` list in `pyproject.toml` (after the existing `PyMuPDF>=1.24` line). Run `uv sync` to install.

2. Verify installation: `uv run python -c "import pymupdf4llm; print(pymupdf4llm.__version__)"`

3. Create `scripts/validate_pdf_math.py` as a standalone script (NO imports from `src/`). The script must:

   **CLI interface:**
   - Accept a positional argument: path to a PDF file
   - Accept optional `--pages` argument for page range (e.g., `--pages 1-10`)
   - Accept optional `--output-dir` argument for where to write JSON report (default: current directory)
   - Use argparse

   **Character classification function (`classify_char`):**
   - Return one of: `'math_operator'` (U+2200-U+22FF), `'private_use'` (U+E000-U+F8FF), `'replacement'` (U+FFFD), `'hangul'` (U+AC00-U+D7AF), `'ascii'` (U+0020-U+007E), `'superscript_subscript'` (U+2070-U+209F), `'arrow'` (U+2190-U+21FF), `'other'`

   **Backend 1 -- PyMuPDF raw analysis (`analyze_with_pymupdf`):**
   - Open PDF with `fitz.open(path)`
   - For each page, call `page.get_text("rawdict", flags=fitz.TEXT_PRESERVE_WHITESPACE)`
   - Iterate through blocks -> lines -> spans -> chars
   - For each character: record codepoint, font name, classification via `classify_char`
   - Aggregate per-page: total chars, count by classification category, list of distinct fonts
   - Flag pages with >0 private_use or replacement chars

   **Backend 2 -- pymupdf4llm markdown analysis (`analyze_with_pymupdf4llm`):**
   - Call `pymupdf4llm.to_markdown(path, page_chunks=True)`
   - For each page chunk: extract the `"text"` field
   - Run same `classify_char` on each character in the markdown text
   - Aggregate per-page: total chars, count by classification category
   - Also record the first 500 chars of markdown output per page for manual inspection

   **Report generation:**
   - Console output: per-page summary table showing page number, total chars, math_operator count, private_use count, replacement count, quality verdict per backend
   - Quality verdict logic: if private_use > 0 or replacement > 0 then "DEGRADED", if math_operator > 0 then "HAS_MATH_UNICODE", else "CLEAN"
   - JSON output: write a `validate_report.json` file containing the full per-page data from both backends, plus metadata (filename, total pages, script version, timestamp)
   - Summary section: overall assessment -- how many pages had degraded output, how many had usable math Unicode, comparison between the two backends

   **Important implementation notes:**
   - The script is a diagnostic/developer tool, NOT a test. It lives in `scripts/`, not `tests/`.
   - Do NOT import anything from `src/`. Use PyMuPDF and pymupdf4llm APIs directly.
   - Include a `if __name__ == "__main__":` guard.
   - Use `unicodedata` stdlib for any additional character name lookups.
   - Handle the case where the PDF file does not exist gracefully (print error, exit 1).
   - Handle the case where pymupdf4llm fails on a page gracefully (log warning, continue).
  </action>
